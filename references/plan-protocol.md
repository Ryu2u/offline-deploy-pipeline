# 规划段协议（纯文本）

生成组件脚本前，必须先产出一份规划文本。规划段**只输出纯文本协议，严禁 JSON，不输出脚本正文**。

## 输出格式

```
===ARTIFACTS===
- 软件名 | 版本 | 架构（版本可 auto=运行时从仓库索引解析）
===ASSUMPTIONS===
- 假设条目（目录/变量等两脚本共同约定写在这里）
===RISKS===
- 风险条目
===VERIFY===
- 验证步骤
===END===
```

包清单段按目标包管理器命名（二选一，与画像 `package_manager` 一致）：

- yum/dnf 目标：`===RPM_PACKAGES===`，条目使用目标 yum/RPM 仓库中的 RPM 包名；**只写包名，不写版本或安装选项**
- apt/dpkg 目标：`===APT_PACKAGES===`，条目使用目标 APT 仓库中的 Debian 包名；**包名不附加架构限定、不写版本号或安装选项**

完整段序：`===ARTIFACTS=== → ===ASSUMPTIONS=== → ===RISKS=== → ===VERIFY=== → ===RPM_PACKAGES=== 或 ===APT_PACKAGES=== → ===END===`

## 包源证据判定（硬性规则）

- 目标包管理器以本次环境画像 `package_manager` 为准；不同包管理器的仓库、包名和查询方式不可混用。
- **不能**根据历史 gotchas、其他发行版/版本/架构/包管理器的经验，推断当前软件源不可访问或当前目标缺少某个包。gotchas（`references/gotchas-kb.yaml`）只作同一环境条件下的参考；来源不匹配时不得引用其 URL 或结论。
- 只有本次请求实际提供的探测输出、HTTP 状态/连接结果或当前目标包管理器查询结果，才能支持"源不可访问"或"包不存在"的断言。没有这类证据时必须写"未验证"，并列出需要执行的具体检查；不得把未验证描述成已确认的失败。

## 规划校验点

产出规划文本后、进入组件生成前，自查：

1. 每个软件的包名只出现在 `===RPM_PACKAGES===` 或 `===APT_PACKAGES===`（与画像一致的那一个）
2. 包名符合白名单正则：RPM `[A-Za-z0-9][A-Za-z0-9+_.-]*`；APT `[a-z0-9][a-z0-9+.-]*`
3. 软件间依赖（如 app 依赖 jdk）在组件顺序中体现：被依赖者排前
4. 目标仓库缺包时（如 aarch64 的 el7 仓库无 nginx，需 EPEL 归档补位），由对应组件 fetch 贡献额外软件源：把该源 repodata 完整下载到 `ARTIFACT_DIR/src/<slug>/`，并在 `ARTIFACT_DIR/conf/<slug>/` 写 `<源名>.repo`（baseurl 指向镜像目录 file:// 或上游 https）；这些包照常写进包清单段
